One purchase, two attempts

The server commits an order for headphones, but the buyer never sees the confirmation. A retry should recover that order without creating a second one.

Independent public labPlaywright · TypeScript · API and browser

The risk

Uncertainty after checkout

A lost confirmation leaves the buyer guessing. The order already exists, but from the browser it looks like checkout may have failed. Generating a new idempotency key on retry could turn one purchase into two orders.

The experiment

Drop the reply after commit

The lab injects the failure after the server saves the order. In the browser test, the original buy button becomes unavailable. The buyer retries the same purchase, and the browser shows the confirmation for order REC-001.

The evidence

Count orders behind the confirmation

The tests inspect the order store and the event journal. The store must contain one order with the expected customer, item, quantity and total. The journal must show two writes with the same key, one commit and one replay.
